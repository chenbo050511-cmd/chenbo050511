# WordMaster · 本地背单词应用

一个跑在自己电脑上的背单词工具。四六级 + 考研词库，按艾宾浩斯遗忘曲线自动排复习，
翻卡和选择题两种模式共享同一套学习进度。数据全部存在本机 SQLite 文件里，不联网、不上传。

```
D:\WordMaster
```

---

## 快速开始

**双击项目文件夹里的 `start.bat`**（不是把它拖到桌面上——见下面那条注意事项）。

`start.bat` 只做一件小事：找到 Node.js，然后交给 `tools/launch.js`。
真正的检查与启动逻辑都在那个 Node 脚本里，它会依次：

1. 确认 `server.js` 就在旁边（不在的话给出明确提示）
2. 确认 Node.js 版本 ≥ 22.5（用到内置的 `node:sqlite`）
3. 如果服务已经在跑 → 不重复启动，直接打开浏览器（会顺带探测 3000/3001/3002）
4. 缺依赖时执行 `npm install`
5. 词库或题库是空的 → 自动下载数据并构建
6. 启动服务并打开浏览器

窗口里会打印地址；**关掉那个窗口就是停止服务**。

> ### 为什么 `start.bat` 里一个中文都没有
>
> 因为 **cmd.exe 是按当前代码页逐字节解析批处理文件的**，里面写 UTF-8 中文会被拆行，
> 报出 `'口，服务就停了。' is not recognized as an internal or external command`
> 这种莫名其妙的错误（真踩过）。
> 所以 `start.bat` 保持**纯 ASCII + CRLF**，所有中文提示都由 `tools/launch.js` 打印。
> **改这个文件时请继续遵守这条。**

> ### 别把 `start.bat` 单独拖到桌面
>
> 它只能看到**自己旁边**的文件。单独复制出去会报
> `Cannot find module 'C:\Users\...\Desktop\server.js'` 之类的一串错。
> 要放快捷方式就右键 → 发送到 → 桌面快捷方式；
> 或者用 `tools/make-shortcut.js`（会带 `icon.ico` 图标）：
> ```bash
> node tools/make-shortcut.js "C:\Users\20232\Desktop\WordMaster 背单词.lnk"
> node tools/verify-shortcut.js "C:\Users\20232\Desktop\WordMaster 背单词.lnk"   # 校验
> ```

浏览器地址：<http://127.0.0.1:3000>。端口 3000 被别的程序占用时会自动往后找 3001、3002……

想手动启动：

```bash
cd /d D:\WordMaster
node server.js            # 打开浏览器
node server.js --no-open  # 不自动开浏览器
```

> **改 `start.bat` 时注意**：批处理文件必须是 **CRLF 行尾**。用 LF 保存的话，
> 双击会出现「窗口一闪而过」或行为异常 —— 这是 .bat 最常见的坑。
> 确认方法：`node -e "const b=require('fs').readFileSync('start.bat');console.log((b.toString().match(/\r\n/g)||[]).length)"`
> 应该等于总行数。用这个命令可以一键转回 CRLF：
> ```bash
> node -e "const fs=require('fs');fs.writeFileSync('start.bat',fs.readFileSync('start.bat','utf8').replace(/^\uFEFF/,'').replace(/\r\n/g,'\n').replace(/\n/g,'\r\n'))"
> ```

## 功能

### 分类体系（三层）

| 层级 | 说明 |
|---|---|
| **词库** | CET-4（3846 词）· CET-6（5406 词）· 考研（4801 词），去重后共 6158 个独立单词 |
| **单元** | 每个词库按**词频从高到低**每 50 词切一个 Unit，所以 Unit 01 就是最该先背的高频词 |
| **筛选** | 首字母 A–Z、词性（n./v./adj.…）、学习状态、是否收藏、是否到期，外加中英文搜索 |

同一个词可能同时属于四级和考研 —— 只存一条，进度共享，在词库里是「多对多」关系。

### 学习方式

- **翻卡片**：看单词 → 翻面看释义/音标/常见搭配/真题例句/词形变化/英文释义 → 三档反馈。
  **卡片一出现就自动朗读**（可在设置里关掉），也不用再去点喇叭；
  重复出现的错词会再读一遍。音色/口音在「设置 → 发音与外观」里选
  - `认识` → 过关，间隔**大步推进**（跳 2 档），下个复习日会拉长
  - `模糊` → 也算过关，但只往前 **1 档**（学到了、没完全想起来。它是真正有区别的
    第三档，不是「认识」的复制品，也不是「不认识」的别名）
  - `不认识` → 不过关，词被**搬到队列后面**、隔 3~5 张再考，直到点会为止
  - 快捷键：`空格` 翻面，`1` `2` `3` 反馈

  > 每档的反馈提示会说实话：「记住啦」/「有点模糊 · 明天再来」/「不认识 · 稍后再考」。
  > 以前「模糊」显示的是绿色「✓ 已掌握」，而同一次点击落库的是「明天重来 + 记一次错」——
  > 看到的和实际发生的完全相反。

  > **排期走三阶段协议**（`first` / `repeat` / `pass`）：
  > 本轮**第一次**作答只记流水、**不排期**；本轮里的重复作答也只记流水
  > （不进正确率、不进打卡）；**过关那一刻**才按「第一次作答的质量」排期。
  >
  > 为什么要延到过关才排期：不认识的词会被重复到会为止，如果第一次不认识
  > 就把它打回阶段 0，那「重复到会了」这件事就白费了。
  >
  > 「第一次作答的质量」存在**服务端**，过关时读出来用 —— 前端传什么都不作数。
  > 这样前端拼错字段不会静默按错误的质量排期，也不会成为一个「改个数就改排期」的口子。
- **选择题**：英→中 / 中→英 / 混合，四选一。干扰项是同词性、长度相近的词，
  不会出现一眼就能排除的弱智选项。答错直接进复习队列。
  - **判分在服务端**：出题时答案留在服务端，前端只拿到选项，
    交卷时只回报「选了哪个」。所以**界面和 devtools 里都看不到正确答案**，
    提交上来的「对/错」也会被忽略、由服务端重新判定。
    （出题响应里既没有 `correct` 标志，也没有指向正确选项的 key。）
  - 同一组题重复提交会被限流（窗口内最多 5 次），防止脚本刷流水。
- **错题本**：答错或标记「不认识」的词集中在这里，可单独清除。
  - 里面单开一块**顽固词**：累计错到阈值（默认 6 次，可在设置里改）的词会被列出来。
    这类词每次都会排在复习队列最前面，光靠重复很难记住，所以给三个出路：
    **写助记**（换个记忆角度）、**暂缓**（不再进复习队列，随时可恢复）、
    **移出错题本**（如果你觉得它不值得花时间）。
    这个思路对标 Anki 的 leech/suspend 机制。
- **助记笔记**：给任何一个词写自己的记忆法（词根 / 谐音 / 场景联想），
  三个地方都能写、失焦自动保存：
  - 翻卡时在**卡片背面**直接写（学到一半想起来就能记下）
  - **词库浏览**的单词详情抽屉里
  - **错题本 / 顽固词**列表里
  笔记存在 `progress.note`，纯本地、上限 500 字符；`data/` 里的数据库就是全部内容。

### 暂停一个词（顽固词）

经常忘的词如果一直硬啃，会长期占掉你复习时间的很大一块。
「暂缓」就是给它一个出口：

- 暂缓后**不再进复习队列**，侧边栏徽标和「今日」的到期数也会同步减掉
  （不会出现「队列里没有、徽标还显示几十个」的矛盾）
- **不打乱排期**：`stage` / `due_at` 原样保留，恢复之后复习节奏跟暂缓前一模一样
- 「已学」统计不受影响 —— 暂缓只是不复习，不代表这个词没学过
- 入口：错题本的顽固词区、词库详情抽屉；
  也可以在「浏览」页用状态筛选 `已暂缓（顽固词）` 找回它们


### 艾宾浩斯排期

`src/srs.js` 里是一张 **6 档「日粒度」间隔表**：

```
1 天 → 3 天 → 7 天 → 15 天 → 30 天 → 60 天
```

- 一次就点「认识」→ 往前跳 **2 档**（新词 → 3 天）
- 点了「不认识」/「模糊」→ 回到第 1 档，也就是**明天**再来
- 阶段 ≥ 4 记为「已掌握」，间隔封顶 60 天
- **刻意不用同一天内的短间隔**。早期版本有 5 分钟 / 30 分钟 / 12 小时三档，
  结果当天反复到期：用户明明做完了，侧边栏徽标又涨回几十上百，看起来像「没做完」。
  间隔落在「天」上就不会有这种自相矛盾（详见下文「学习方式」里的过关规则）

每天打开应用，只有到期的词会出现在复习队列里 —— 不用自己安排，也不会积压。
首页和统计页都能看到未来 7/14 天的复习负载预测。

> **阶段标签只有一处定义**。统计页的「记忆分布」标签和卡片上的「下次复习」文案
> 都来自 `src/srs.js`（统计接口会下发 `labels`）。
> 曾经前端手抄过一份 10 档的旧表，排期改档后没人同步，
> 于是同一个词在翻卡页显示「明天」、在统计页显示「5 分钟」。**改间隔表时只需改一处。**


### 真题题库（短文阅读 / 段落匹配）

**58 套四六级真题**（2019 年 6 月 ~ 2025 年 12 月），做完即时批改并定位到原文。

| 题型 | 数量 | 说明 |
|---|---|---|
| 短文阅读 | 107 组 / 527 题 | 四选一，考试时 5 题一组 |
| 段落匹配 | 57 组 / 549 条陈述 | 从 A–O 段落里给每条陈述找到出处 |

- **筛选**：级别（CET-4 / CET-6）、题型、年份、状态（没做过 / 做过 / 有错题）、标题搜索
- **做题**：左边原文、右边题目；段落匹配点段落字母可高亮对照
- **划词标记**：点**原文或题目**里的任意单词，弹出五个颜色的色板（黄/绿/蓝/红/紫），
  选一个就给这个词加同色下划线；再点同一个词可以换色或用 ✕ 清除；
  点空白处收起。**标题栏还有一个「清除划线 N」按钮，一次清掉整套卷的划线**
  （会先确认，且只影响当前这套卷）。标记按套卷存在浏览器里，交卷复盘时还在
  （一个例外：**答题时**选项不能划 —— 点选项是选答案；交卷后就可以划了）
- **分段排版**：阅读短文按**真实段落**显示，不是一整块文字（70/107 组，拿不到的退回整段，
  见下方说明）
- **交卷后给解析**：
  - **答错的题自动展开解析** —— 真题原版解析，含「定位到第几段 + 逐项排除理由 + 知识点」
  - **答对的题收起**，旁边一个「查看解析」，想看再点（不想被剧透的可以直接跳过）
  - 段落匹配额外给出**正确答案所在段落**的原文
  - 解析来自题库自带的 `explanation` 字段，覆盖率 **741/1077（69%）**：
    短文阅读 71%、段落匹配 67%。源数据没有解析的题就不显示解析块
- **批改**：交卷后逐题标对错，阅读给出正确选项，匹配直接引用正确段落的原文
- **成绩**：每套记录做过几次、最好成绩、用时；「做题记录」页看趋势，「题目错题」页集中重做
- **未作答按错计分**：分母永远是整组的题数，漏答不会让分数虚高

> 段落匹配的原文来自 OCR，字母标记在源数据里有四种写法（行首 `A)`、行内 ` A)`、
> 紧贴正文 `A)How will`、方括号 `[A]`），构建脚本用「候选 + 按字母顺序贪心接受」
> 统一处理，所以 58 组里保住了 57 组。少数卷的正文被 OCR 截断，
> 答案指向的段落根本不在正文里 —— 这类「无解」的题会被丢弃（共 27 条），
> 因为一道永远做不对的题比没有这道题更糟。

## 部署到别的电脑（不用再下载任何东西）

第一次部署慢，是因为启动脚本要去 GitHub 下载 62.9 MB 的全量词典。
但其实**建好的数据库 `data/wordmaster.db` 里什么都有** ——
6158 个单词、164 组真题、741 条解析、70 组分好的段落，全都在这一个文件里。

所以部署的正确姿势是**把数据一起带走**，而不是让新机器重新下载：

```bash
node tools/pack.js            # 生成 dist/ 部署包（约 14 MB）
```

把 `dist/` 整个文件夹拷到目标机器，双击里面的 `start.bat` 就能用 ——
**一个字节都不用下载，也不用 `npm install`**（依赖已经打进去了）。

打包脚本会：
1. 先把 SQLite 的 WAL 合进主库（只拷 `.db` 会得到一个内容不全的数据库，踩过）
2. 打进「源代码 + 前端 + 依赖 + 数据库 + 重建用的精简数据」
3. **自检**：拷完立刻查一遍单词/真题/分段/解析的数量，不通过就直接报失败 ——
   不会让你拷一个坏包出去

排除了 `tools/_raw/exam/pdf`（21MB）和 `answerkey`（6.8MB）：
它们只在「重新推导段落分段 / 核对答案」时才用，结果已经写进数据库了。
需要那份能力时从原目录补拷这两个文件夹即可。

> 如果你只是想手动拷贝，最少需要这些：
> `server.js` `package.json` `src/` `public/` `node_modules/` `start.bat` `data/wordmaster.db`
> （`tools/_raw/` 可以完全不带 —— 运行时根本不读它，只在重建词库/题库时才需要）

### 真的要下载时的兜底

万一目标机器上连数据库都没有，`start.bat` 会调用 `tools/fetch-assets.js` 去下载。
它比原来的 `curl` 直连强在：

- **多镜像自动切换**：直连失败会依次换 `ghfast.top` / `gh-proxy.com` / `ghproxy.net`
  （都实测可用）。国内网络慢时加 `--mirror` 可以优先走镜像
- **有进度和实时速度**（`已下载 12.4 MB 46% 0.6 MB/s`），不会看着像卡死
- **数据齐了就一个字节都不下**
- 下完会自动生成精简词典，之后重建不再需要那 62.9 MB

- **常见搭配 + 真题例句**（卡片背面）：
  - **常见搭配**：从 Tatoeba 英文语料（2000 万词）统计出来的常用搭配，
    如 `condition → good condition / critical condition / living conditions`
  - **真题例句**：这个词在真题正文里出现的一句原话，句中的目标词会高亮
  - 数据由 `tools/build-phrases.js` 生成，存在 `word_phrases` 表；
    **覆盖 85% 词库 / 已学词 99%**
- **学新词 / 复习 分开**（左侧导航两个入口，不再混在一个会话里）
  - **学新词**：一批 5 个（`batch_size` 可调），一批全部过关再进下一批。
    **每日新词量只是「目标」不是硬上限** —— 达标了也能继续学，想学多少学多少
    （今天已达标时按钮会写「继续学新词 · 今日已达标 N 个」）
  - **复习**：取**全部到期的词**，按**错误次数从多到少**排
    （错误分 = 不认识×3 + 模糊×1 + 测试做错×2），老是记不住的词每次都排前面。
    **同样不设硬上限** —— 之前 daily_review 会截断队列，导致「页面说复习完了、
    侧边栏徽标却还显示 99+」（额度用光但还有到期词没排进去）。现在日目标只用于进度显示
- **过关规则（学新词和复习一样）**
  - 点「认识」→ 过关，下次间隔往前跳 2 档
  - 点「模糊」→ 过关，下次间隔只往前 1 档
  - 点「不认识」→ 词被**搬到队列后面**、隔 3~5 张再考，直到点会为止
  - 排期只看**第一次**作答：第一次「认识」→ 跳 2 档；第一次「模糊」→ 跳 1 档；
    第一次「不认识」→ 明天再来。
    所以「本轮重复到会」会改变**这次过不过关**，但不改变排期依据的质量 ——
    该明天复习还是明天（这也是原设计的意思：重复到会有价值，但不该被当成「已掌握」）
- **下次复习时间**：间隔表是**日粒度 6 档** —— `1 天 → 3 天 → 7 天 → 15 天 → 30 天 → 60 天`
  - 「认识」→ 往前跳 **2 档**（新词 → 3 天；3 天 → 15 天；15 天 → 60 天）
  - 「模糊」→ 往前跳 **1 档**（3 天 → 7 天）
  - 首答「不认识」→ 回到第 1 档，也就是**明天**再来。**lapse 之后第一次答对会正常跳档**，
    不会因为「不许倒退」被卡住（惩罚是有意的，不该被抖动规则吃掉）
  - 封顶 60 天
  - **每个间隔都带 ±5%~15% 的抖动（fuzz）**，防止同一批学的词永远在同一天一起到期。
    参数照抄 Anki（`< 2.5 天不抖`，`(2.5,7] ±15%`、`(7,20] ±10%`、`(20,∞) ±5%`），
    并且带一条**「不许倒退」**保护：抖动不能把间隔压到上一次的间隔之下，
    否则同一档位反复到期时会越抖越短、等于白复习一轮
  - **刻意不用同一天内的短间隔**（曾经有 5 分钟 / 30 分钟 / 12 小时三档）。
    那种设计会让当天反复到期，用户明明做完了、侧边栏徽标又涨回几十上百，
    看起来就像「没做完」。间隔落在「天」上就不会有这种自相矛盾。
    这一条**与 Anki 官方在 FSRS 文档里的建议一致**：同日多次重复对长期记忆
    贡献不显著，官方建议把 learning steps 数量压到最少
  - 老的 10 档数据会**按间隔就近平移**到新 6 档（`due_at` 不动，不打乱你当前的节奏），
    由 `db.js` 里的 `migrateOnce('srs_v2')` 一次性完成。
    **这个迁移是幂等的**：它按数据内容自判（存在 `stage >= 6` 才是旧格式），
    所以「恢复出厂设置」把标记弄丢之后重启也不会把新数据再压一遍
- **统计口径**：正确率**只算第一次作答**；重复作答与过关归档都不计入，
  重复次数单独累计并在本批结束时展示。
  「今日」页和「统计」页共用同一个口径常量（`util.js` 的 `accuracyModes()`）——
  以前两处各写各的，同一份数据显示 96% / 94% 两个数

### 界面主题（白色 / 深色，可随时开关）

两套主题，两个入口：

- **「今日」页右上角**的「白色 / 深色」按钮 —— 常用的入口
- 或者「设置 → 发音与外观 → 界面主题」用分段按钮选

切换是**立刻生效并记住**的：状态同时写进浏览器 localStorage 和服务端设置，
所以刷新页面不会闪一下再变（`<head>` 里有一段内联脚本在样式表生效前就把主题定下来了），
关掉浏览器再打开也还是你选的那个。

白色主题不是简单地把背景刷白，而是整套语义色都重新配过 ——
深色主题里那套亮色（亮绿 `#10b981`、亮橙 `#f59e0b`、亮青 `#0ea5e9`）放在白卡片上当小字
根本看不清，所以白色主题下它们整体压深了一档，对比度达标。

## 词库是怎么来的

数据源是开源词典 [ECDICT](https://github.com/skywind3000/ECDICT)（77 万词条）。
`tools/build-dict.js` 做了这些事：

1. 按 `tag` 字段抽出 `cet4` / `cet6` / `ky` 三个词表
2. 清洗释义：ECDICT 用字面量 `\n` 分词义、用 `[医]` `[经]` 标注专业领域 —— 拆行、剥离领域标记
3. 从释义里解析出词性并归一化（`a.`→`adj.`、`vt.`→`v.`）
4. 音标规范化：西里尔 `ә`→IPA `ə`、`:`→`ː`、`'`/`,`→`ˈ`/`ˌ`
5. 解析词形变化 `d:abandoned/p:abandoned/...` → 「过去式: abandoned · 过去分词: …」
6. 全局去重 + 按词频排序 + 每 50 词切 Unit

重建词库（**会清空学习进度**，先导出备份）：

```bash
node tools/build-dict.js --force
```

数据文件缺失的话（正常不会，除非你把 `tools/_raw/` 删了）：

```bash
node tools/fetch-assets.js            # 自动补齐，多镜像 + 进度显示
node tools/fetch-assets.js --check    # 只看看缺什么，不下载
node tools/fetch-assets.js --mirror   # 国内网络慢时优先走镜像
```

> 精简词典 `ecdict-slim.csv`（1.7MB）和全量 ECDICT（62.9MB）构建出来的结果**完全一致**
> （6158 词、283 个 Unit，已验证），所以正常情况下不需要全量词典。
> 想要的话自己抽一份：`tools/make-slim-dict.js` 会把它压到 1.7MB。

> **已知取舍 —— 阅读短文的分段是「从试卷 PDF 找回来的」**
>
> 源题库里的阅读正文是一整块（107 组里 106 组连换行都没有），直接显示就是一面文字墙。
> 所以额外做了一步还原：**107 组里 87 组拿到了真实分段（81%）**，共 598 个段落。
> 剩下 20 组的 PDF 是**扫描件**（没有文字层，`extract_text()` 返回空），
> 需要 OCR 才能拿到段落，目前退回整段显示。
>
> 也就是说：分段是「有则更好」，拿不到的时候不会给出错误的分段。

### 阅读短文的分段是怎么还原的

试卷 PDF 有完整文字层，而且**段落首行比正文左边距缩进约 35pt**（实测 92.3 vs 56.8）——
这是排版系统留下的确定信号，比猜行间距可靠得多。`tools/extract-paragraphs.py` 的做法：

1. **用库里的题号当锚点**，在 PDF 里定位 `Questions 46 to 50 are based on the following passage.`
   （不能拿库里的题号区间精确匹配 —— 清洗时可能丢过题，库里是 Q46-49 而卷子印的是 46 to 50，
   所以改成「找出所有引导句、挑区间包含 q_from 的那个」；
   个别卷子这行被截断成只有 `Questions46to50`，再兜底只用题号区间）
2. 从锚点后取到第一道题之前，得到正文的所有行
3. **滤掉水印噪声**：这些 PDF 在正文中间插了 `pastpapers.cn`、页码、
   `2022年6月英语四级真题 第一套` 之类的页脚，不滤掉会被当成正文段落拼进去。
   注意要「先抠掉水印再判断」，不能整行丢弃 —— 水印常常和正文黏在同一行
4. 按每行 `x0` 找出缩进行 → 初步切分
5. **再用「段落必须以句末标点收尾」修正边界**：不满足就把这段并回上一段。
   这一条很关键，单靠缩进会把「引号开头的续行」也当段落首行，
   加上这条校验后切分失败率从 16/58 直接降到 0
6. **PDF 只用来算分段位置，文字仍用库里已有的** —— 因为有一种卷子的 PDF 提取出来整行没有空格
   （`Onlineclassesbegantobepopularized...`），文字没法直接展示，但它的行坐标依然准确。
   所以最后把每段开头的几十个字符当探针，在库里的正文中按顺序定位，换算成字符区间去切。
   探针长度从 80 字逐步退让到 14 字，容忍 OCR 的零散差异
7. **段首探针找不到时，改按段尾映射** —— 有些卷子 PDF 的**阅读顺序本身是乱的**
   （pdf 里是 `hairdresser about katharine abraham an economics professor…`，
   正文却是 `Katharine Abraham, an economics professor, was chatting with her hairdresser…`）。
   这类按段首永远对不上，但**段尾是好的**。换一头当探针、再把边界**向前吸附到最近的句末**，
   把「映射失败」从 15 组降到 0

> **切分位置有两个坑，都会静默产生错数据，只能靠校验发现**：
> - **归一化下标 ≠ 原文字符下标**。匹配是在「只留字母数字」的串上做的，
>   所以段尾若直接用 `源下标[末尾] + 1`，会把每段最后的**句号**一起切掉
>   （症状：所有段落结尾都没有句号）。必须往后补回句末标点
> - **相邻两段不能共用同一个字符**。下一段段首若带左引号，
>   拿「下一段第一个字母的位置」当上一段的终点，这个引号就会同时出现在两段里
>   （症状：上一段以 `. “` 结尾，下一段又以 `“` 开头）。要先把段首换算成「含前导引号」的位置

> 不要把整段拿去和库里正文精确比对 —— 库里的正文来自 OCR，
> 和 PDF 文字总有漏字、标点差异、专有名词拼错，整段比对必然失败。
> 只匹配每段开头（或结尾）的一小段就足够定位边界了。

### 怎么确认分段没切错

`tools/check-paragraphs.py` 对每一段做不变量校验，比肉眼看样例可靠得多：

- 段落文本必须能在正文里**按顺序**找到
- 段首应当大写或引号/括号开头（英文段落不会以小写词开头）
- 段尾应当是句末标点
- 段落数 2–16、每段不短于 60 字符
- 把所有段落拼起来应当**几乎覆盖整篇**正文

这个校验第一次跑就抓出 472 处问题（其中「所有段落都丢了结尾句号」是切分逻辑的 bug），
修完降到 17 处（占 598 段的 2.8%）——剩下的多半是**正文本身就没有标点**的 OCR 遗留，不是分段的错。

重建（需要先下载 PDF，**会清空已有的分段结果**）：

```bash
pip install pdfplumber
python tools/fetch-exam-pdf.py           # 只下含文字层的卷子
python tools/extract-paragraphs.py --write
python tools/extract-paragraphs.py --report   # 看失败汇总
python tools/diagnose-paragraphs.py           # 逐组诊断卡在哪一步
python tools/check-paragraphs.py              # 分段质量自检（不变量校验）
```

> **关于「少了一题」**：源题库本身有少数题缺失（不是导入时丢的）。
> 全库 164 组里有 11 组题号不连续：
> - **10 组是段落匹配**：源数据的正文被 OCR 截断，答案指向的段落根本不在正文里，
>   这些「无解」的题被主动丢弃（一道永远做不对的题比没有更糟）
> - **2 组是短文阅读**：`2025-12-CET4-1` 缺 Q48、`2023-03-CET4-1` 缺 Q52
>
> 其中 Q48 已用 `tools/repair-missing-questions.py` 从试卷 PDF 补回
> （题干和四个选项来自 PDF，答案取自官方答案页 = A）。
> 补题的难点是那份 PDF 丢空格（`dowhenprescribingmedicine`），
> 所以先用 `tools/fix-spacing.py` 做**基于词典的最小代价分词**还原。
> Q52 那份 PDF 是扫描件，暂时补不了。

> **关于解析的来源和清洗**：解析是题库自带的真题原版解析
> （格式：`<正确答案>. 详解：定位第X段…B项错误…C项未提及…涉及知识点：细节理解`），
> 不是生成的 —— 这类内容必须用权威来源，编出来的解析会教错东西。
>
> 但它是 OCR 出来的，有三个毛病，`tools/import-explanations.js` 里逐个处理：
> 1. **硬换行断在句子中间**（"研究人\n员"）→ 逐行拼接时判断两侧字符，
>    中文直接接上，英文单词被断才补空格
> 2. **页脚水印混进正文**（`四级2019年6月20`、`46四线2025.6`）→ 正则剥掉
> 3. **开头混进了题目译文和四个选项**（一大段乱码）→ 按标记优先级裁剪：
>    优先从 `【定位】`/`【解析】`/`【精析】` 开始截，而不是 `【答案】` ——
>    后者后面往往还跟着一串选项碎片

> **文本清洗（单词粘连 / 混进来的试卷名）**
>
> 源数据的正文是 OCR 出来的，有两类脏东西，`tools/clean-exam-text.py` 负责清：
>
> 1. **单词粘连**（本该有空格的地方丢了空格）：`shoppingwhere` → `shopping where`、
>    `prescriptionmedications` → `prescription medications`、
>    `servicesinsideschools` → `services inside schools`、
>    `theU.S.economyisrightontrack…` → `the U.S. economy is right on track…`
> 2. **正文里混进试卷名/页脚**：`Recent studies have 四级2020年12月6 shown that` →
>    `Recent studies have shown that`；
>    `busy schedules. 2022 年 6 月英语四级真题 第一套 页码 7 But after…` → `busy schedules. But after…`
>
> 最后清掉 **58 处试卷名 + 约 150 处粘连**，全库已无残留。
>
> **这一步的难点是「别改坏真词」**。踩过的坑，也是规则为什么长这样：
>
> - **「词典里没有」≠「就是粘连」**。第一版直接拿分词切所有非词典词，结果
>   `caregiving → care giving`、`Kickstarter → Kick starter`、`Petridish → Petri dish`、
>   `kleptoplasty → klepto plasty` 全切坏了 —— 合成词、品牌名、术语 ECDICT 当然没有。
>   所以改成：**真词一律不碰**；只在「虚词/代词/副词」边界切；
>   只有 ≥15 字符的非词典词才交给 DP 分词
> - **判词用的词表要过滤**。ECDICT 原始词表里混着 `obes`（4 字母、无词频）这类碎片，
>   拿它当判据会把 `obesity-inducing` 切成 `obes ity-inducing`
> - **但过滤太狠会误伤变形词**。`is` / `an` 这些常用小词在 ECDICT 里词频是 0，
>   被「无词频且短于 5 字母不成词」挡掉后，`conversationalistis` 就切不出 `conversationalist is`。
>   所以补了一份**无条件算词的白名单**
> - **长词要显式保护**。阈值降到 15 后，`Personalisation`（ECDICT 里没有英式拼写）会被切成
>   `Personal is ation`。所以扫描全库 ≥15 字符的 token（79 个），
>   逐个人工分出 74 个合法长词写进 `NEVER_SPLIT`
>
> 两条使用约定：
> - **默认只预演**，用词级 diff 把每一处改动打出来；确认后才加 `--write`
> - 写库前自动备份到 `data/wordmaster.db.before-clean`
> - 需要**全量 ECDICT**（`tools/_raw/ecdict.csv`）来判词，精简词典不够用；
>   它只在重跑清洗时需要，删掉后可用 `node tools/fetch-assets.js` 再取

### 真题库是怎么来的

数据源是开源项目 [ShepiTT/CET_practice_questions](https://github.com/ShepiTT/CET_practice_questions)
（四六级真题 + OCR 出来的官方答案）。`tools/build-exam.js` 负责：

1. 按文件名解析出试卷信息（`2019-06-CET4-1.pdf` → 2019 年 6 月四级第 1 套）
2. 只取 `reading`（短文阅读）和 `matching`（段落匹配）两种题型，其余（听力、选词填空）不要
3. **段落切分**：见上文「四种字母标记写法」的说明
4. **OCR 清洗**：
   - 标点缺空格 —— `cycle.This` → `cycle. This`，`ago,the` → `ago, the`（规则只在大写字母前补空格，
     所以 `2.5`、`e.g.`、`U.S.` 都不会被误伤）
   - 粘连词 —— `ofabandonment` → `of abandonment`。这里**故意做得很保守**：
     只有当 token 不在 ECDICT 词表、且开头正好是常见功能词、剩下的也是合法词时才切。
     因为像 caregiving / emailing / texters 本来就是完整单词（只是 ECDICT 没收录），
     任何「两半都是词就切」的激进规则都会把它们改坏
5. 丢弃正文被 OCR 截断导致「无解」的题目

重建（**会清空做题记录**）：

```bash
node tools/build-exam.js --force
```

源库没下载过的话：

```bash
node tools/fetch-assets.js
```

> 已知取舍：源数据的**阅读正文没有任何段落标记**（107/108 组连换行都没有），
> 所以短文阅读的正文是按一个整块渲染的，不像原卷那样分段。
> 这不影响做题（题目的答案不依赖段落结构），只是排版上略逊。段落匹配不受影响，
> 因为它的段落本来就要按字母切开。

## 环境要求

- **Node.js ≥ 22.5.0**（需要内置 `node:sqlite`；本机用的是 v22.22.2）
- 浏览器：Edge / Chrome 等 Chromium 内核（朗读需要支持 Web Speech API）
- 不需要 MySQL、不需要 JDK、不需要构建工具链

### 网络暴露：默认只监听本机

服务**默认只绑定 `127.0.0.1`**，同一 WiFi 下的其他设备访问不到。

这是刻意的：所有接口**都没有认证**，其中「恢复出厂设置」能清空你的全部学习记录。
而界面和本 README 都承诺「数据不出本机」，把服务开到局域网就和这句话矛盾了。

确实要用手机 / 平板打开时，显式指定：

```bash
HOST=0.0.0.0 node server.js      # Windows cmd: set HOST=0.0.0.0 && node server.js
```

这时启动横幅会打印醒目警告。**开了它就等于把你的学习数据放到局域网上**，
请只在自己信得过的网络里这么用，用完改回默认启动即可。

### 这几个脚本各自防的是什么（都是踩过的坑）

- **`check-srs.js`** —— 排期算法是唯一「算错了也不报错、只会静默按错的间隔排期」的地方。
  这里防：三档反馈是否真的各跳各的档、fuzz 是否留在允许带内、
  **抖动是否可能让间隔倒退**（同一档位反复到期时越抖越短 = 白复习一轮）、
  lapse 之后是否还能正常推进（惩罚不能被「不许倒退」吃掉）。
- **`check-consistency.js`** —— 防「**同一个概念在多处各自实现**」。
  「未学 / 已学 / 到期 / 正确率」四套判定在多个接口里必须给出**同一个数**。
  这里出过的具体事故：徽标 108、统计页 109（统计页那份漏了排除暂缓词）；
  今日页 96%、统计页 94%（两处各写各的 `mode IN (...)`）。
- **`check-study-phases.js`** —— 防三阶段协议退化。前端曾经固定发 `'legacy'`，
  于是服务端的 `first`/`repeat` 分支是死代码，连带「今日已复习」**恒为 0**。
  现在防：`first` 不排期、`repeat` 不进正确率、`pass` 才排期、
  **`pass` 不采信前端传的 `firstRating`**、没有首答记录时 409、重复 `pass` 被拒绝。
- **`verify-quiz-grading.js`** —— 防判分退化。伪造 `correct: true` 必须被判错，
  session 失效必须 409 而不是「退回信前端」，wordId 对不上必须跳过不写库。
  判分一旦回到「信前端」，**作弊是静默生效的**，光看界面发现不了。
- **`check-new-word-survival.js`** —— 防「给未学的词写笔记/收藏/暂缓，它就从学新词里消失」。
- **`check-migration.js`** —— 防「恢复出厂设置后重启，进度被二次迁移」。

> 通用教训：这个项目里凡是「同一个概念在 SQL 里写了不止一遍」，
> 迟早会出现两处不一致。现在「未学」「已学」「错题」「正确率」四个判定都抽成了
> `src/util.js` 里的单个函数（`isUntouched` / `isStarted` / `isMistake` / `accuracyModes`），
> **改口径只改一处**。

## 想改点什么

- **间隔曲线太激进/太保守** → `src/srs.js` 的 `INTERVALS` 数组（单位：分钟）。
  改完**不用动前端** —— 统计页的阶段标签由接口下发（见 `srs.stageLabels()`）
- **各档跳几档**（认识 +2 / 模糊 +1）→ `src/srs.js` 的 `EASY_JUMP` / `VAGUE_JUMP`
- **抖动幅度** → `src/srs.js` 的 `FUZZ_BANDS`（照抄自 Anki 的 fuzz.rs）
- **顽固词阈值** → 应用内「设置 → 学习计划 → 顽固词阈值」，或 `leech_threshold`
- **每天任务量** → 应用内「设置 → 学习计划」，或 `src/db.js` 的 `DEFAULT_SETTINGS`
- **配色** → `public/css/app.css` 顶部令牌区，那是**唯一**的颜色定义处。
  `html[data-theme="dark"]` 和 `html[data-theme="light"]` 分别覆盖各自的主题色。
  要加第三套主题（比如护眼绿）就照抄一个 `html[data-theme="xxx"] { ... }` 块，
  再去侧边栏按钮和设置页的分段按钮里加上对应选项即可。
  **别在别处写颜色字面量** —— `tools/check-colors.js` 会拦住（连 JS 里也不许，
  JS 要用颜色就读令牌或写 `var(--*)`）。浅色主题下语义色要**整体压深一档**，这个已经做好
- **字号 / 间距 / 圆角** → 同一处令牌区：

  | 令牌 | 值 | 用途 |
  |---|---|---|
  | `--fs-display / h1 / h2 / h3` | 62 / 25 / 20 / 17px | 大分数 / 页面标题 / 区块标题 / 卡片标题 |
  | `--fs-body / sm / xs / xxs` | 15 / 13 / 12 / 11px | 正文 / 次要说明 / 标签 / 极小注释 |
  | `--sp-1 … --sp-8` | 4 / 8 / 12 / 16 / 20 / 24 / 32 / 48px | 间距（4 的倍数） |
  | `--r-sm / md / lg / xl` | 8 / 12 / 18 / 24px | 按钮·输入框 / 次级卡片 / 主卡片 / 弹层 |

  **存量没有批量替换，这是有意的**：原先实际用到 25 种字号、114 种间距取值，
  硬换成阶梯会把刻意调过的尺寸拉平（`11 / 11.5 / 12 / 12.5 / 13px` 挤在
  2.5px 区间里是层级，不是随手写）。令牌的价值是「**新代码有据可依**」，请从这里取。
  圆角已把 7/9/10/11/20px 这些明显离群的值收敛掉；
  **2–6px 是留给微小内联元素的**（高亮词背景、`kbd`、序号角标、热力图格子），
  它们用 `--r-sm` 会显得过圆，所以有意保留为字面量 —— 别当成漏改
- **动效** → 统一用 `var(--ease)`，时长 0.15–0.6s。
  全项目已有 `@media (prefers-reduced-motion: reduce)` 全局降级
  （系统开了「减少动态效果」就把动效压到 0.01ms），加新动效不用额外处理
- **单元大小**（默认 50 词）→ `tools/build-dict.js` 的 `UNIT_SIZE`，改完要 `--force` 重建
- **加新词库**（比如雅思/托福）→ 在 `build-dict.js` 的 `BOOKS` 里加一项，`tag` 填 ECDICT 的标签
  （可用标签：`zk` `gk` `cet4` `cet6` `ky` `toefl` `ielts` `gre`），然后重建
- **在数据库副本上做试验** → 有写操作的功能（移除错题、清空进度…）别拿真实数据试。
  `WM_DB` 可以把数据库指到别处，另起一个实例互不干扰：
  ```bash
  # 先备份出一份副本（连同 WAL/SHM 一起复制才是完整状态）
  cp data/wordmaster.db* /d/tmp/copytest/
  WM_DB=D:/tmp/copytest/wordmaster.db PORT=3999 node server.js --no-open
  ```
